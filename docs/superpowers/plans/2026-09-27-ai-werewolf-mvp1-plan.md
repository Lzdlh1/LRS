## 8.1 M1 实施记录（2026-09-27）

**结果**：154 个测试用例全部通过，`tsc --noEmit` 干净，随机对局 40 局全部正常结束且**零非法 Action**。

**实施中对契约做的调整**（原设计未覆盖，编码时才发现）：

| 调整 | 原因 |
|---|---|
| `chief_withdraw` 增加 `withdraw: boolean` | 退水环节需要同时表达「退水」与「不退水」，只有一个方向的 Action 无法让 AI 作出完整选择 |
| 新增 Action `chief_transfer`（target 可为 null） | 警长死亡后需要决定移交警徽还是撕毁；null 表示撕毁 |
| PHASES 新增 `CHIEF_TRANSFER` | 警徽去向必须在遗言之前处理 |

**相对设计文档的简化**（已知差异，后续按需补）：

| 简化 | 现状 | 影响 |
|---|---|---|
| 发言起点 | 固定为「警长下一位开始，顺时针，警长最后」；无警长则从最小座位号开始 | 设计文档写的是「起点由警长指定」。少了一个博弈点，但不影响胜负判定 |
| 第二天换手 | 未实现 | 发言顺序每天相同 |
| 狼队刀人 | 由座位号最小的存活狼代表提交 | 狼队内部协商属于 agent-host 的职责，M3 实现 |
| 黄金回放 fixture | 改为「同种子重放结果完全一致」+ 手写黄金用例 | 生成 fixture 的独立脚本在 Node 类型剥离下跨包解析复杂；确定性与手写断言覆盖了同样的回归需求 |

**已实测覆盖的边界情况**：同守同救、女巫自救限制、猎人被毒死不能开枪、守卫连守排除、平票 PK 再平票、警长 1.5 票、首夜死者照常参与竞选、狼刀在先。

## 8.2 M2 实施记录（2026-09-27）

**结果**：184 个测试用例全部通过；已在真实浏览器里实测——连接、点击提交行动、连续代打、视角切换、打完一整局（狼人胜）全部正常。

**技术选型调整**：

| 原计划 | 实际 | 原因 |
|---|---|---|
| Fastify | 原生 `node:http` | 当前只需要健康检查 + WS 升级，引入框架没有收益；将来需要路由/插件再换 |
| better-sqlite3 | Node 24 内置 `node:sqlite` | 免去原生编译，Windows 上省掉一大类环境问题 |
| tsc 构建产物 | 无构建步骤 | Node 24 原生剥离类型，直接 `node src/index.ts` 即可跑 TS |
| 前端 Pinia | 一个 composable | 全局只有一个 store，`ref` + 函数足够，不引入额外抽象 |
| 默认视角 = 玩家视角 | 默认上帝视角 | M2 用于人工验证规则，看全场更方便；**M4 会改回玩家视角** |

**开发中发现并修掉的两个真问题**：

1. **vitest 里 `ws` 客户端连不上服务端**（独立 Node 进程正常）。端到端测试改用 Node 内置的 WHATWG `WebSocket` —— 反而更贴近前端真实路径，测试从 20 秒超时变成 81 毫秒通过。
2. **小视口下圆桌把底部操作区顶出屏幕**（浏览器实测时按钮点不到）。已改为：滚动收在中间区域内部 + 圆桌按视口高度分档等比缩放，保证操作区在任何高度下都可见可点。

**这一里程碑实际交付的可玩路径**：`npm run dev:server` + `npm run dev:web`，浏览器打开 http://localhost:5173 —— 一个人可以扮演全部 9 个座位从头打到尾，并用「代打」按钮快速跑完。

## 8.3 M3 实施记录（2026-09-27）

**结果**：214 个测试用例全部通过。用假大脑（MockProvider）验证了完整链路：**8 个 AI 自动行动，真人只在自己回合点一下，一整局能自动跑完，全程零非法行动**。真实模型效果待 Key 到位后验证。

**开发中发现并补上的引擎缺口**：

- 引擎从没发出过 `action_requested` 事件 —— 契约里定义了、设计文档也写了，但状态机只是把待办塞进 `state.pending` 就完事。已补发（私密可见），这样整局事件日志是自包含的，复盘和 AI 记忆都靠它。

**为共用而做的结构调整**：

- 「把引擎选项摊平成可提交动作」的逻辑从 web 移到了 core-engine。前端按钮和 AI 决策必须用同一份「现在能做什么」，两边各写一套迟早在某个边界情况下漂移。

**相对设计文档的简化**：

| 简化 | 现状 | 影响 |
|---|---|---|
| 摘要层（M3） | 用**确定性压缩**：从事实层直接生成每日要点，不额外调模型 | 零成本、零幻觉；代价是不会「把一段发言提炼成一句话」，只保留结构化事实 |
| 狼队协商 | 由座位号最小的存活狼代表决策，队友的当前判断会出现在它的提示词里 | 有信息对齐，但没有多轮讨论；狼队配合深度不如真人 |
| 无 Key 时的行为 | AI 提交兜底动作，游戏仍能完整跑完 | 方便本地调试；日志会明确警告「未配置任何可用的 LLM Key」 |

**验证方式**：单元测试 + 真实 WebSocket 端到端（真假大脑两种）+ 服务器实际启动（健康检查返回 `ai:false` 时说明未配 Key）。

## 8.4 M4-1 实施记录：流式输出（2026-09-27）

**结果**：用真实 DeepSeek 在浏览器里实测通过 —— 发言是逐字长出来的，不是一次性蹦出来。

**改动链路**：

```
Agent.composeSpeech  →  router.stream() 每来一个增量就调 onSpeechDelta
AgentHost            →  按座位号转发给房间
GameRoom             →  广播 { type: 'stream', seat, delta }
前端 useGameSocket   →  累积成 streaming 状态
EventLog             →  日志末尾一行带光标的「直播行」
RoundTable           →  中心显示「N 号发言中」+ 说话座位呼吸高亮
```

**几个刻意的取舍**：

| 取舍 | 原因 |
|---|---|
| 流式片段仍以 `spoke` 事件为最终依据 | 流是"草稿"，事件才是"说了什么"。落地时用事件里的干净文本替换，避免两套真相 |
| 发言流不做视角过滤 | 发言本来就是公开信息（大家都听得到）。真正的信息隔离仍由事件裁剪负责 |
| 额外发一条 `stream-done` | 不然一旦这次行动被丢弃（局面已变），前端光标会一直闪 |
| 显示层压平换行 | 模型输出里有 `\n\n`，而最终落地文本会把空白压成单空格。不统一的话，正式发言落地那一刻看起来像「文字被改了」 |

**实测确认**：抓到了 `4 号发言中` / `6 号发言中` 两段实时增量；`speakingSeat: "6"` 证明座位高亮生效；`思考中`（AI）与 `等待`（真人）区分正确；浏览器控制台零错误。

**测试**：215 个用例全绿（新增 1 个流式端到端用例：断言流式拼接结果与最终 `spoke` 文本完全一致）。

## 8.5 M4-2 实施记录：并行预思考（2026-09-27）

**先纠正一个原定目标。** 设计文档里 M4-2 的验收标准是「用户发言结束后，下一个 AI 几乎立刻开口」，这条**字面上做不到**：下一个 AI 的判断必须建立在真人刚说的那句话之上，提前算就等于让它凭空猜。

所以实际做的是**能真实并行、且语义正确**的那部分 —— 把「规则上本来就是同时发生」的阶段一次性问完：

| 阶段 | 能否预思考 | 依据 |
|---|---|---|
| 上警、退水 | ✅ 可以 | 每个人决定时并不知道别人怎么选，待办彼此独立 |
| 发言 | ❌ 不行 | 后发言的人必须听到前面说了什么 |
| 放逐投票 | ⚠️ 暂时保持串行 | 依次投票、票型公开，后面的看得到前面的票 |

规则知识留在引擎里：新增 `concurrentBatch(state)` 返回「当前阶段剩下的待办能否一次问完」，返回 null 表示只能一个一个来。房间不猜规则，只负责按它发起并行。

**实测数据**（一局真实 DeepSeek 对局）：

| 指标 | 数值 |
|---|---|
| 一局耗时 | **185.7 秒**（105 次调用） |
| 全部调用延迟的串行累加 | 301.4 秒 |
| **被并行隐藏掉的时间** | **约 115 秒（38%）** |
| `chief_signup` 实际发起跨度 | 12.0s（串行会是 58.0s） |
| `reflection` 每批 8 次发起跨度 | 2.4s（串行会是 24s） |
| `speak` 发起跨度 | 169.6s —— **严格串行，符合规则** |

**顺手修掉两个真 bug**（都是这轮测试逼出来的）：

1. **AI 上一阶段的行动会被误当成当前阶段的行动提交。** `runAiTurn` 原先只比对座位号 —— 但同一个座位可能在下一个阶段又被点到，于是夜里的「刀人」会被当成「上警」提交。现在改成用完整的合法性校验（这个行动是否仍在当前待办的可选项里）。
2. **`isStillAllowed` 对发言待办永远返回 false** —— 因为 `choicesFor` 不给「发言」生成按钮。上面那个修复一上线就把 AI 发言全丢了，对局直接卡死。发言阶段改为只校验「是不是该座位在发言」。

这两条也说明：**「只比座位号」这种看似够用的校验，在多阶段状态机里是不够的。**

**另外把「模型调用完成」日志从 debug 提到 info** —— 每次调用的延迟与 token 是调优和成本看板的核心数据，之前被默认级别丢掉了，导致根本无法按任务分析延迟。

**测试**：217 个用例全绿（新增 2 个：一个断言「真人还没动手，8 个 AI 的决策已全部发出且发起时间跨度 < 200ms」，一个断言「发言阶段不会有人被提前预跑」）。修复前该用例 6 次里失败 3 次，修复后 6/6 稳定。

**关于「继续压缩耗时」的决定：不做。**

延迟在这里**是节奏，不是缺陷** —— 真正的狼人杀对局本来就不短，AI 太快反而让人跟不上、失去在脑子里盘逻辑的时间。所以：

- 投票保持「依次投票」（后面的看得到已亮出的票型，更接近线上 App 的体感）
- 投票保持 strong 档，不为了省时间降级到便宜模型
- 已实现的并行**只用在「规则上本来就是同时发生」的阶段**，不为了提速去改玩法

> 后续若有人想「优化」这块（把投票并行化、给发言加预取），请先回来看这条。

## 8.6 M4-3 实施记录：视角切换（2026-09-27）

**默认视角改回玩家视角**（1 号），上帝视角变成右上角的调试开关。切换本身 M2 就能用，这一轮真正的工作是**修掉玩家视角下的两处信息泄漏**：

| 泄漏 | 后果 | 修法 |
|---|---|---|
| 夜间下发 `pending.seat` | 夜间顺序是固定且公开的，「现在轮到 8 号」**等于直接告诉所有人 8 号是守卫** | 新增 `masked`：旁观者在夜间既看不到「轮到谁」，也看不到阶段细节 |
| 死讯公布前下发 `alive` / `deathCause` | 变体 A 下首夜死讯在**上警之后**才公布，而引擎在结算夜晚时就写入了死亡状态 —— 期间玩家的屏幕上会提前看到谁死了、死于狼刀还是毒 | 死讯未公布前对外一律算「在场」，与引擎自己的 `onBoardSeats` 同一口径 |

第二处特别值得一提：它依赖「变体 A 让首夜死者先参与上警」这个规则选择 —— 如果当初选了变体 B（先公布死讯再竞选），这个泄漏就不存在。**规则一变，信息边界也得跟着变。**

**实测（浏览器，真实对局）**：

| 检查项 | 结果 |
|---|---|
| 默认视角 | `我的视角 · 1 号`，座位 1 标记为「我」 |
| 玩家视角下别人的身份 | 不显示（`玩家2`、`玩家3`… 无身份） |
| 自己的身份与狼队友 | 正常显示（`玩家1 · 狼人`、`你的狼队友：2 号、5 号`） |
| 夜间旁观 | 阶段只显示「夜晚」，中央「天黑请闭眼」，**不点亮任何座位**，无行动选项 |
| 切到上帝视角 | 阶段细节 + 行动座位 + 药水 + 全部 9 个身份立刻可见 |

**顺带**：女巫的药水数量做成顶部状态条（`🧪 解药 0 · 毒药 1`），这也是「夜间面板随视角变化」的一部分。

**测试**：219 个用例全绿。新增 2 个锁死上面两处边界的用例，并把原来那条「非行动者能看到座位号」的用例改成只在白天成立 —— 夜间保密是有意为之，不是回归。

## 8.7 M4-4 实施记录：复盘视图（2026-09-27）

右上角「复盘」按钮 → 全屏面板：顶部按天切换，中间事件与 AI 决策合并成一条时间线，AI 推理依据以卡片形式插在它发生的那一刻。

**数据来源**：事件用房间内存里的本局完整事件流（`history`）；AI 决策新增 `onDecision` 回调，由 `AgentHost` 在每次决策完成后回报，房间记进 `decisions`（重开一局清空）。**没有新建表** —— 复盘只服务「本局回看」，落库属于投机性设计；推理依据同时提到了 `info` 日志，需要离线分析时从日志里捞。

**信息边界**（这一轮真正的设计点）：

| 内容 | 局中 · 玩家视角 | 局中 · 上帝视角 | 局终 |
|---|---|---|---|
| 事件 | 照旧走 `eventsFor` 视角裁剪 | 全量 | 照旧裁剪 |
| AI 推理依据 | **封存** | 可见 | 可见 |
| 9 张底牌 | **封存** | 可见 | 可见 |

推理依据里直接带着身份信息（「我是狼，队友是 2、5」），局中让玩家看到等于把牌翻过来打。所以封存条件是 `viewer !== 'god' && state.winner === null`。

**顺带修掉的两处**：

1. AI 决策日志原先停在 `debug`，默认级别下被丢弃 —— 推理依据哪儿都没留下来。提到 `info`。
2. 复盘面板最初把「第 0 天」当开局做了特判；核对引擎后确认 `createGame` 的起始 `day` 就是 1，从不产生 day 0，把这段死代码删了。

**实测（浏览器，真实对局）**：

| 检查项 | 结果 |
|---|---|
| 玩家视角打开复盘 | 显示封存提示；无底牌 chips；无决策卡片 |
| 玩家视角的事件裁剪 | 时间线只出现 `你的身份：狼人`、`你的狼队友：7 号、9 号`、`轮到 1 号行动` 这类自己该看的，seq 中间的跳号正是被别人视角过滤掉的私密事件 |
| 切到上帝视角再打开 | 封存提示消失，9 张底牌 chips 全亮，时间线里出现 2 号守卫的决策卡片（`guard_protect` / `calm` / 完整 reasoning 与立场） |
| 天数切换 | `第 N 天` 按钮按 `history` 里出现过的天生成，点击即请求该天 |

**测试**：222 个用例全绿（新增 3 条：`onDecision` 回调、局中封存、局终解封且私密事件仍按视角裁剪）。

## 8.8 M4-5 实施记录：用量看板（2026-09-27）

顶部「用量」按钮 → 全屏面板，与复盘同一套交互。数据走 WS（`{type:'usage', scope}` → `{type:'usage', payload}`），没有新增 HTTP 路由。

**范围**：`本局` / `全部历史` 两个 tab。看本局时按局拆分是空数组 —— 一行没有意义；看历史时才带 `按局` 表（join `games` 拿牌型、开始时间、胜负）。

**踩到的两个坑**：

1. **SQL 行不能直接断言成 camelCase 的类型**。第一版把 `SUM(in_tokens) AS in_tokens` 断言成 `UsageBucket`（字段是 `inTokens`），类型检查放过去了，运行时会全是 `undefined`。改成 `UsageAggRow`（下划线字段）+ `toBucket()` 映射。
2. 顺带摸清了 `node:sqlite` 的类型脾气：**只有 `type` 别名才会被 TS 赋予隐式索引签名**，`interface` 不行 —— 用 `interface` 写行类型时 `as X[]` 会报「neither type sufficiently overlaps」。这条写进了代码注释，免得下次再撞。

**顺带**：`play-game.ts` 里的消息判断从「排除法」改成正面判断 `snapshot|update`，这样以后再加消息变体不会又把它绊倒。

**实测（浏览器，真实数据 11 局）**：

| 检查项 | 结果 |
|---|---|
| 本局 tab | 13 次调用 / 13,105→3,679 tokens / ¥0.1087 |
| 全部历史 tab | 933 次调用 / 881,219→233,564 tokens / ¥5.4904 |
| 三个分组互相印证 | 按任务 12 行合计 933 = 按模型 3 行合计 933 = 按局 11 行合计 932 + 1 条 `game_id` 为空的记录 933 ✓ |

| 失败调用 | 分组键为空串的行显示为「（调用失败）」（router 在调用失败时不上报 model，却有 154 条这样的记录 —— 这是 M4 期间真实踩过的失败，不是脏数据） |

## 8.9 M4-6 实施记录：信息边界穷举审计（2026-09-27）

M4-3/M4-4 那两处泄漏是靠读代码 + 手工点几下发现的，只覆盖了「我当时想得到」的地方。这一轮换思路：**让机器去撞**。

`packages/server/test/e2e.test.ts` 新增一组「信息边界穷举审计」：

1. 挂一个上帝视角连接当对照组（必须看得到 9 张底牌，否则整套断言等于空转）；
2. **1~9 号逐个当真人连上去，各开一局新的、代打到底**；
3. 这一路上收到的**每一帧原始报文**都留下来 —— 不只是带状态的那些，stream / replay 也留着；
4. 用一组不变量扫每一帧，最后再对原文做一次不看结构、只看字符串的兜底扫描。

**不变量清单**：

| 不变量 | 说明 |
|---|---|
| 别人的 `role` 必须是 null；自己的必须对 | 身份 |
| 死讯未公布前，别人的 `alive` 必须仍是 true、`deathCause` 必须是 null | 这是 M4-3 修过的第二处泄漏，现在被永久锁住 |
| `witchPotions` 非空 ⟺ 观察者就是女巫 | 药水 |
| 别人的 `pending.options` 必须是空数组 | 选项 |
| 夜间阶段里，非行动者根本不该看到 `pending` | 夜间顺序固定且公开，下发座位号等于点名 |
| `role_assigned` / `seer_result` / `action_requested` 的 seat 必须是我自己 | 私密事件 |
| `wolf_teammates` 只能发给狼 | 狼队 |
| 原文里不出现别人身份的 `"role":"x"`；不出现 `sk-` 开头的串 | 兜底 |

**关键一步：证明这套审计能失败。** 一个不会失败的测试等于没测，所以我做了两次变异注入：

| 注入 | 结果 |
|---|---|
| `role: player.role`（身份照发） | ✅ 立刻抓到：`泄漏：1 号视角看到了 2 号的身份: expected 'guard' to be null` |
| `masked` 恒为 false（夜间不遮蔽） | ❌ **第一次没抓到** —— 我原来的夜间不变量只写了「masked 为真 ⇒ pending 为 null」这一个方向，把服务端自己的标志关掉后就绕过去了 |

第二处暴露的是测试自身的缺陷：不该相信被测对象自己算出来的标志。改成**直接看 `phase`**：只要处于 `NIGHT_*`，非行动者就不该有 `pending`。改完再注入，抓到了（`泄漏：夜间旁观者（1 号）看到了「轮到谁」: expected { seat: 4, options: [], … } to be null`）。

**顺带澄清一处「看着像泄漏、其实不是」**：

- `game_over` 事件里带 `reveal: [{seat, role}]` —— 终局亮底牌是刻意的，所以原文扫描对这一帧开豁免（豁免写在代码注释里，免得以后被当成漏检）。
- 夜间向下发的是**真实阶段名**（`NIGHT_SEER` 等），前端只把展示文案遮成「夜晚」。夜间四个子阶段的名字和顺序本来就是公开信息，真正致命的是座位号，所以这里没有遮。

**必须写清楚的边界（别把它当成安全证明）**：

**这套东西没有做认证。** `setViewer` 是客户端说自己是谁，服务端就信 —— 玩家把视角切到上帝、或者直接改报文，就能看到全部底牌。这是「上帝视角开关」这个功能本身要求的，也是本地单人项目的合理取舍；但它意味着**信息边界是一道 UI / 合规边界，不是针对恶意客户端的安全边界**。哪天要联机、要上服务器，第一件事就是给每个连接绑定座位并移除客户端的 `setViewer`。

**测试**：226 个用例全绿（新增 2 条审计，覆盖 9 局 × 每帧）。

## 8.10 界面重做与公网部署（2026-09-27）

### 视觉：把「圆桌」真正做成主角

方向定为**月下圆桌**：底色压到近黑并带一层冷调月色，只留三个语义色 —— 月光（periwinkle，主色）、朱砂（狼/出局）、赤金（警徽），好人/自己用青玉。标题走楷体（`Kaiti SC / KaiTi`），正文无衬线，数字等宽。桌面上加了一圈暗盘 + 中央缓慢呼吸的月色，压一层几乎看不见的胶片颗粒消色带。

**真正的问题不在配色，在几何。** 原先的圆桌是 460×480 固定尺寸，靠四条 `max-height` 媒体查询分档 `scale`。实测 390px 宽的屏幕上：桌子右边被切掉 36px，**5 号与 6 号座位跑到了屏幕外面**。

改成**连续自适应**：

| 原来 | 现在 |
|---|---|
| 固定 460px + `transform: scale()` 分档 | `aspect-ratio: 1` + `max-width: min(100%, 680px, calc(100dvh - 250px))` |
| 座位坐标算 px | 坐标算百分比，配 `translate(-50%,-50%)` —— 座位永远正压在环上 |
| 字号写死 | 全部用容器查询单位 `cqmin`，桌子多大会自动跟着变，**没有断点** |
| 姓名标签单独一行 absolute（会被省略号截断） | 姓名收进座位圈里，身份做成角标单字（狼/预/女/猎/守/民） |

三种宽度实测（改前 → 改后，`scrollWidth == clientWidth` 即无横向溢出）：

| 视口 | 改前 | 改后 |
|---|---|---|
| 390×844（手机） | 桌子 414 宽、**右侧被裁** | 桌子 370 宽，9 个座位全在屏内；日志 270 高，操作区不出屏 |
| 834×1112（平板） | 桌子 460、日志在下 | 桌子 560，日志 806×367，无溢出 |
| 1440×900（桌面） | 桌子 460 只占左栏，下面 270px 空着 | 桌子 680 居中，日志成 460 宽的右栏，铺满 |

其余：日志里**发言单独排版**（左侧月光竖线 + 浅底），事件与对白一眼分得开；操作区按钮改成网格（点目标不再七零八落），触屏下按钮撑到 42px；`prefers-reduced-motion` 下全部动效关掉。

### 部署：一个端口搞定

- 服务端新增**静态托管**（`config.webDir`），带路径穿越防护：请求必须落在 dist 之内，找不到实体文件回 `index.html`（SPA）；`/assets/` 长缓存，入口页 `no-cache`。部署只需要开一个端口。
- 新增 **`ACCESS_TOKEN` 门**：设了口令后，`?token=xxx` 换 cookie（HttpOnly、重定向掉地址里的 token），HTTP 与 **WS 握手**共用同一道判定。没设口令时完全不设防 —— 本地开发行为不变。
  - 这一步是必须的：应用本身没有账号体系（见 8.9），而每一次 AI 发言都是真钱。

服务器侧：Node **v24.21.0** 装到 `/opt/node24`（走官方 tarball，不用 apt 源），代码在 `/opt/lrs`，systemd 服务 `lrs`（开机自启 + 崩溃自重启），监听 `0.0.0.0:7039`。

**两台机器之间的网络现实（值得记一笔）**：服务器**连不上 GitHub**（`GnuTLS recv error`），但 npm registry 与 `api.deepseek.com` 都通。所以部署走「本地打包 → scp → 解包」，而不是服务器上 `git clone`；`npm ci --omit=dev` 在服务器上装运行时依赖（ws/zod）。

### 顺手抓到的一个真问题：闲置的服务会自己把整局打完

部署完回头看日志，发现**没人在线也在烧钱**：4 分钟里 17 次真实模型调用。

原因链很清楚：真人座位的待办超时（15~90 秒）→ 引擎提交兜底动作 → 轮到 AI → AI 发起真实模型调用 → 再轮到真人 → 再超时……一局就这么自己走完了。

修法是**两道闸，都挂在「有没有人在看」上**：

| 闸 | 位置 | 行为 |
|---|---|---|
| 不装超时计时器 | `armTimer()` | `subscribers.size === 0` 时直接返回，不排定时器 |
| 不发起 AI 行动 | `scheduleAi()` | 同上，且不跑预思考 |
| 接上 | `subscribe()` | 人一连上来就重新装表 + 重新调度；`unsubscribe()` 到最后一个人时清表 |

按物理意义讲这也更对：超时兜底是**为「有人在等」而存在**的，没人在等就不该有兜底。

实测：重启后空置 110 秒，模型调用数 **34 → 34（差 0）**，局面完全冻结；用带口令的地址连上去，日志立刻出现 `guard_protect` 真实调用，用户看到「夜晚 · 狼人行动 / 等待 1 号」。新增 1 条用例把这件事钉住（`没人看着的时候不推进`）。

**当前状态**：227 个用例全绿，`/health` 报 `ai:true web:true`，公网地址带口令可玩。

## 8.11 对局刹车与设置界面（2026-09-27 · 公网部署后）

上一节末尾那句「空置时不烧钱」只解决了**没人连接**的情况。真正用起来才发现两个洞：

### 一、界面开着没人管，照样能把一局打完

真人座位的待办会超时（15~90 秒），兜底动作一提交，轮到 AI 就是真实调用 —— 浏览器标签页挂着不动，一晚上足够把额度走掉一截。用户提的正是这件事。

**三道闸，全部挂在「谁在看、谁在按」上**：

| 闸 | 触发 | 行为 |
|---|---|---|
| 没人看 | 最后一个连接断开 / 没人连过 | 不排超时计时器、不发起 AI 行动（人一连上自动接上） |
| 暂停 | 顶栏「⏸ 暂停」 | 计时器清掉、AI 不调度、**外部推进一律拒绝**（`submit` 直接丢弃并记 warn） |
| 中止 | 顶栏「中止」 | 终态：不恢复、不下发待办，只能「新开一局」 |

界面上状态是显式的：顶栏有 `⏸ 已暂停 · 不再消耗` / `已中止` 的标签，桌面中央写「已暂停 / 局面冻结中，不会消耗模型调用」，操作区按钮直接收起来（点了也会被服务端丢掉，不如不给点）。

实测：暂停 40 秒（跨过 20 秒的上警超时），事件序号一动不动；点继续后 30 秒内正常推进到下一阶段。用例方面新增 3 条（暂停冻结 / 继续接上 / 中止是终态）。

### 二、Key 只能改 `.env`，新设备也无从「启用」

设置界面（顶栏「设置」）现在管三件事：**写 Key、看 Key、换供应商**。

**存储**：都用早就建好但一直没用的 `settings` 表。优先级 **界面 > `.env`**，`.env` 只当首次部署的兜底。有个细节值得记：界面里把 Key 清空时，存的是**空串**而不是删行 —— 否则清掉之后 `.env` 里那把会悄悄顶回来，用户会以为「我明明关了」。

**两道锁，各管一件事**：

| 锁 | 管什么 | 形态 |
|---|---|---|
| `ACCESS_TOKEN` | 整个站点 | URL 带一次 → 换 HttpOnly cookie |
| **管理口令** | 只管设置这一块 | `scrypt` + 16 字节随机盐存哈希；解锁后发 30 天会话 cookie；连错 5 次冷静 60 秒 |

也就是说：**新设备打开设置页，必须输一次口令**才能看或改 Key —— 正是用户要的那层。改口令会把其它设备的会话全部踢掉。口令忘了没有后门（服务端只有哈希），所以界面上留了「修改口令」入口，避免走到改库那一步。

**Key 的展示**：状态接口里永远只有掩码（`sk-abc••••••cdef`）和来源（界面 / `.env` / 未配置）；只有点了「查看」才会把**当前真正生效的那把**取回来一次 —— 所以 `.env` 里配的 Key 也看得到（不然界面上会是一段空白，让人以为没配）。这一条也写进了用例。

**换供应商**：`deepseek` / `openai` / `自定义（OpenAI 兼容，需填 http(s) 地址）`，两个档位各自填模型名。保存后**重新装配模型路由**，对下一局生效，正在跑的那局还用旧的。测试覆盖：非法供应商 / 空模型名 / 非 http 地址一律 400 且不落库。

**安全边界（要说清楚）**：站点是明文 HTTP。点「查看」的那一刻，Key 会以明文经过网络到浏览器 —— 所以在不可信网络下不要点它；真要传输，更稳的是直接粘贴覆盖、而不是查看。服务器上 Key 与口令哈希都落在 `/opt/lrs`（与 `.env` 同级信任），日志里从来没有 Key 或口令原文。

**实测（公网地址，真实交互）**：首次进入 → 要求设口令 → 设完进表单（供应商 deepseek、两个模型名已填、Key 显示「（来自 .env）· 当前就用它」）→ 点查看拿到 35 位 `sk-` 开头的完整 Key → 保存提示「已保存。对下一局生效」→ 锁定后立刻退回解锁页；**重启服务后再打开，同样要求解锁**（会话只在内存里，天然做到了「新设备/新进程要口令」）。

验收完把测试口令与测试写入的设置行都从库里清掉了，所以现在的状态是「口令未创建」：**谁先打开设置，谁设口令**（也就是本人）。

**测试**：239 个用例全绿。设置后台单独 8 条：掩码不泄明文、未解锁改不动、口令长度与哈希、清空语义、查看与锁定、改口令踢会话、连续错 5 次冷静、非法参数。

## 8.12 界面重构与五个功能（2026-09-29 · 手机实测后）

实际用手机玩了两局之后的问题清单，以及逐条的处理。

### 一、顶栏组件太多，挡视野 → 折叠栏

原来「继续 / 中止 / 视角 / 复盘 / 用量 / 设置 / 新开一局」七颗按钮 + 四个状态标签全挤在一行，手机上换行占掉两三行高。现在顶栏只留**信息**（`第 N 天 · 阶段`、`我的座位 · 我的身份`、暂停/中止标签、连接灯），**操作**全收进 `☰` 折叠栏。

两个细节：

- 折叠栏是**占位的一行**，不是浮层 —— 浮层会压住最上面那两个座位，点不到（用户规则里的「碰撞体积」）。
- **暂停时「▶ 继续」单独提到顶栏**：这是唯一需要立刻够到的按钮，不能藏在折叠栏里。暂停标签也留在顶栏，所以「现在不烧钱」随时看得见。

### 二、站位改左右两列 → 顺手把日志放到中间

圆桌换成左右两列：`Math.ceil(n/2)` 分左，其余分右。九人局 5 + 4，十二人局自然 6 + 6，**不需要改布局代码**。座位卡尺寸由 `--col-w` / `--avatar` 两个变量定，`--avatar` 还夹了一层 `6.2vh` —— 屏幕矮的时候自动缩小，一侧 6 个也塞得下。

圆桌中央那块本来是 `stage`（显示「几号发言中」「已暂停」等），现在整块让给**事件日志**，输入框紧贴在日志下面。文字局全靠读日志，实测 436×557 的窄窗口里日志拿到 **385px 高**（约七成屏高），原来是 160px。

### 三、标注身份：情报标在头像上，不用回头翻日志

`marks.ts` 从**已按视角裁剪过的事件流**里归集，纯展示、不做推断：

| 来源 | 标记 |
|---|---|
| `seer_result` | 目标头像上压「好」/「狼」角标 |
| `wolf_teammates` | 队友全部压「狼」 |
| `witch_night_info` | 被刀的人加一个「🗡 昨夜被刀」小角标（不冒充阵营判断） |
| `seats[].role` | 自己（或上帝视角）的座位角上印身份单字 |

关键点：入参就是裁剪后的事件，**拿不到的信息在这里也不可能凭空出现**。另外顺手在顶栏加了「7 号 · 狼人」这一枚标签 —— 自己的底牌不该靠翻日志找。4 条用例覆盖查验/队友/夜刀/空输入。

### 四、点头像做选择：不再铺一屏按钮

`choicesFor(pending)` 里带 `target` 的动作（刀、验、毒、救、守、票、移交、开枪）不再渲染成按钮网格，改成：

- 目标座位变成可点的 `button`，带月光脉动光晕，**卡面上直接写「投 6 号」**；
- 操作区只留一句「点两边闪光的头像选目标（N 个可选）」+ 不需要选人的按钮（上警 / 退警 / 不用药 / 弃票 / 放弃开枪 / 撕毁警徽）；
- **同一个人身上有多个动作**（女巫的解药与毒药落在同一个人）时弹一个小菜单问清楚，绝不默认替他选一个。

### 五、随机位次

`GameRoom.startNewGame` 用同一个 `rng` 先抽座位再发牌（固定种子依然能整局复现），并把它作为 `humanSeat` 下发到前端；`defaultViewer` 新增 `'human'` 语义 —— 每开一局视角跟着挪，不再写死 1 号。`newGame` 时把原先坐在旧座位的订阅者一起搬过去，否则真人会莫名其妙看到别人的牌。

### 六、昼夜与环节：把「平滑」改成「看得见」

- **昼夜**：两层背景（`.bg-night` / `.bg-day`）叠着淡入淡出，比切 `background-image` 平滑。切换时全屏放一幕：太阳/月亮从地平线升起 + 「天亮了 · 第 N 天」/「天黑请闭眼」。
- **环节**：`CSS` 里给每个环节配一个「章节标题」（🎖 警长竞选 / 🌅 公布死讯 / 🕯 遗言 / 🔫 猎人开枪 / 🗳 放逐投票…），切换时一闪而过（1.8 秒）。
- **两条不加动画的规矩**：① 夜里 `masked` 时**一条环节动画都不放** —— 夜间顺序是公开的，「现在是预言家验人」等于直接说谁是预言家；② 用「局号 + 昼夜」当钥匙，**刚连上、刷新页面不算一次昼夜切换**，否则每次刷新都要被糊一脸「天亮了」。

### 实测（436×557 窄窗口，真浏览器交互）

| 检查 | 结果 |
|---|---|
| 九个座位是否都在屏内 | 是（左右 7~429，上下 87~513，均不越界；`scrollWidth`/`scrollHeight` 等于视口，无溢出） |
| 日志高度 | 385px（折叠栏打开时 296px） |
| 折叠栏 9 颗按钮是否真能按到 | 逐个中心点 `elementFromPoint` 命中自己（`hitSelf: true`） |
| 随机位次 | 连续几局真人座位在 1~9 之间变化，本局是 7 号（狼） |
| 身份标注 | 自己的座位印「狼」，队友 2 号 / 4 号头像上压「狼」角标 |
| 点头像投票 | 放逐投票时 8 个座位闪光并写「投 N 号」，点 6 号 → 日志出现「票型：6 号 1 票；6 号被放逐」 |
| 昼夜动画 | 白天 `app day`；入夜捕捉到 `app night` + `.sky.night`「天黑请闭眼」；天亮捕捉到 `.sky.day`「天亮了 第 4 天」 |
| 环节动画 | 捕捉到 `.flash.speech`「💬 依次发言」 |
| 刷新页面 | 不放「天亮了」（用局号做钥匙），底色直接落到当前昼夜 |

**测试**：247 个用例全绿（新增 4 条身份标记、2 条随机位次）。其中原来的「并行预思考」用例改成座位无关的写法 —— 真人不再固定在 1 号，上警是 1 号先答，得一路推到「轮到真人上警」为止才能断言那 8 次预思考。

## 8.13 「AI 凭空引用还没发生的发言」与身份标记的时间门控（2026-09-29 · 手机实测第二轮）

### 一、先发言的人引用了一段还没发生的话

现象（第 1 天·竞选发言，说话顺序 3 → 4 → 5）：

```
3 号（竞选发言）：不是，5号你这也太急了吧？警上直接甩查杀……我验的就是他，查杀！
4 号（竞选发言）：3号5号俩人都跳预言家还互相甩查杀……
```

3 号第一个说话，却像在回应 5 号的查杀；4 号更是把 5 号还没说出口的话当成了既成事实。用户的原话是「它会虚构一个信息，然后沿着这个信息发言，后面的发言也跟着这个虚构初始信息来」。

**根因不是模型胡说，是真的把未来的信息喂进去了**：

- 上警（`CHIEF_SIGNUP`）是**并行预思考**阶段，8 个座位的决策在同一瞬间产出（见 8.5）。
- 每个决策里都带一个 `claim`（「我要跳预言家」）。而 `AgentHost.act()` 在**决策产出的那一刻**就 `recordClaim()` 写进了公共事实层。
- 于是「# 公开的身份宣称」里，在任何人开口之前就已经列着 8 条宣称 —— 3 号读到「5 号自称预言家（我验了 3 号是查杀）」，就照着它编出了「5号你太急了」；4 号读到同一条，就说「俩人都跳预言家」。

**验证**：把修复临时撤掉跑新增用例，第一条断言直接报 `expected [ …(8) ] to deeply equal []` —— 正好 8 条，和推理完全对上。

**修复**（`agent-host/src/host.ts`）：

| 改动 | 说明 |
|---|---|
| 宣称改成「说出口才算数」 | `act()` 里只把 claim 存进 `unspokenClaims`；`observe()` 收到 **`spoke` 事件** 时才 `recordClaim()`。房间是先 `observe` 完这一批事件再叫下一个人行动，所以先说话的人先入库，后说话的人一定看得到 |
| 只认「发言」带出来的 claim | 夜里那一手、上警那一票附带出来的 claim 只是计划，一律不入库（`action.kind === 'speak'` 才收） |
| 隔天的计划作废 | 攒着一直没说出口的话，第二天再开口时不再当作今天的宣称 |
| 私有笔记同步延后 | `agent.ts` 里「你跳了预言家」这条自我笔记原本也在决策时写，会让 AI 以为自己已经报过身份了 —— 挪到真的发言那一刻 |
| 提示词加一条硬约束 | 「只引用『# 本轮发言』里确实出现过的话：还没人说过的事，不要当成已经发生」 |

### 二、自己的座位认不出来

顶栏虽然有「4 号 · 平民」，但两列站位上没有任何一处标明哪个是自己，玩家得回头翻日志数座位。现在自家座位：

- 头像左上角一块**实心青玉「我」牌**（比加粗边框认得多）；
- 名字位置直接换成底牌（「平民」/「狼人」/「预言家」），因为「玩家N」这种名字没有信息量。

实测：436px 宽的窄窗口里「我」牌落在 `[7,336]-[26,353]`，头像 32×32，两者只在角上重叠，没有溢出、没有横向滚动条。

### 三、身份标记要跟着「什么时候才知道」

原来的标记是「收到事件就摆出来」，等于把信息位的时间线压扁了。现在：

| 标记 | 什么时候才摆出来 |
|---|---|
| 预言家查验的好/狼 | 事件本身就是「出结果后」才产生，天然正确（只显示自己查过的那几张） |
| 狼队友 | **首夜狼人睁眼之前不摆**（准备 / 守卫阶段隐藏，进入狼人阶段那一刻起显示）—— 狼也得等碰过面才知道队友是谁 |
| 女巫夜里的「被刀」 | 拿到 `witch_night_info` 才有 |

**关于「狼人不知道狼王是谁、狼王知道狼人是谁」这类牌子差异**：标记只认「服务端发给我这个视角的事件」，不做任何推断。所以谁该知道谁，定义权只在引擎的 `visibility` 一处 —— 将来加 12 人板（狼王）时，只要让引擎按牌子发对应的 `wolf_teammates`，标记会自动跟着变，前端不用改代码。当前 9 人板里没有狼王，因此没有可观察的差异。

**测试**：249 个用例全绿（新增 2 条：宣称公开时机、碰面之前不摆队友标记）。

## 9. 已知风险与回退方案

| 风险 | 回退方案 |
|---|---|
| `better-sqlite3` 在 Windows + Node 24 原生编译失败 | 改用 Node 24 内置 `node:sqlite`，store 层接口不变 |
| DeepSeek 推理质量撑不住狼人杀 | 关键决策切到更强 provider —— llm-router 已抽象，只改配置 |
| 8 个 AI 串行发言延迟过高 | M4-2 预思考；必要时白天发言改为「只让关键玩家详细发言」 |
| 引擎规则与你的预期不符 | 规则参数在 `rules.ts` 集中配置，改一处即可，不动状态机 |
| **连接没有认证**：`setViewer` 由客户端自报座位/上帝视角 | 本地单人玩法里这是特性不是缺陷。公网部署时用 `ACCESS_TOKEN` 在 transport 层挡一道（见 8.10）；真要联机，先给连接绑定座位并移除客户端的 `setViewer`（详见 8.9） |
| **站点是明文 HTTP**：点设置里的「查看」时，Key 明文过网 | 自用尚可（两道口令 + 只在可信网络点查看）。要正经用就上 HTTPS，或干脆用 SSH 隧道访问 7039 |
